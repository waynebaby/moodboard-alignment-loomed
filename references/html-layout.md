# HTML 统一布局规范

目标：无论输入是影视、海报、PPT、游戏、App、品牌，最终 HTML 都保持同一种视觉气质和页面骨架。项目类型只影响节点语义和字段权重，不改变整体布局。

## 固定页面骨架

所有 HTML 使用同一结构：

1. Hero 首屏
   - 项目名
   - 整体风格定位
   - 关键词 tags

2. Summary 摘要卡
   - 一句话定调
   - 项目类型 / 视图 / 节点集合 / 版本
   - 已对齐共识
   - 风险提醒

3. Palette 关键色板
   - 色块、色名、Hex、用途

4. Direction Nodes 方向节点
   - 左侧：1:1 情绪图或占位图
   - 右侧：节点标题、节点元信息、六维说明
   - 每个项目类型都使用同一个 node card
   - 图片卡片保持 1:1 统一布局；点击图片可打开 lightbox 查看原始比例完整图，不改变 node card 布局

5. Footer + 内联 data.json

## 统一视觉风格

固定为：
- 暖米色纸感背景
- 白色/米白卡片
- 细边框
- 大圆角
- 低强度阴影
- 棕金色 accent
- 大量留白
- 移动端单列，桌面端图文双列

HTML 默认亮色，并内置亮/暗切换按钮；用户选择通过 localStorage 记忆。打印 / 导出 PDF 时强制亮色，保证可读性和低墨量。主题切换只属于 view 层，不改变 data.json 中的审美方向、色板或项目调性。

不要根据项目类型改变整体 CSS 风格。即使是赛博朋克、游戏、科技项目，也只在生成图、色板和文字中体现风格，不改 HTML 容器气质。

## 项目类型如何映射到统一节点

| 项目类型 | 数组字段 | 节点显示名 | 统一解释 |
|---|---|---|---|
| film | timeline | 时间节点 | 影片情绪推进中的关键帧 |
| mv | timeline | 音乐段落 | 音乐结构中的视觉段落 |
| poster | frames | 视觉方案 | 单帧主视觉或变体 |
| brand | frames | 品牌触点 | 品牌定调/场景/质感延展 |
| ppt | slides | 页面节点 | 演示稿中的情绪页面 |
| app | journey | 用户旅程 | 用户路径中的界面状态 |
| game | states | 互动状态 | 玩家体验中的状态节点 |

HTML 不为不同类型创建不同布局，只在文案标签中体现语义差异。

## 节点卡片固定结构

每张 node card 固定为：左侧图片 + 右侧内容区。

右侧内容区根据项目类型和视图裁剪维度（详见 `project-templates.md` 和 `view-templates.md`）。不在裁剪范围内的维度不显示，但 data.json 中始终保留字段。

Sound 在海报/品牌/PPT/App 中默认不进入 node card，如有需要可在执行层注意中提及；若项目本身是声音驱动体验，可通过 `meta.sound_enabled: true` 强制显示 sound/audio。

Image Prompt 仅在 execution 视图中显示。

## 不允许

- 不要为 PPT 单独做 PPT 页面布局。
- 不要为 App 单独做 UI mockup 布局。
- 不要为海报单独做画廊布局。
- 不要为影视单独做横向时间轴布局。
- 不要因项目风格改变 HTML 的全局 CSS 气质。

统一 HTML 是对齐容器，不是成品视觉稿。项目风格由图像、色板和文字承载。
